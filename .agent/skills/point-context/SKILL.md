# point-context

## 언제 쓰는가

팀원이 30포인트 중 한 포인트를 발표·집필·검증용으로 준비할 때. 레포 링크만 던지면 AI가 `source/`나 `chapters/`(기번 영문 원전 계통, 다른 책)를 헤매다 엉뚱한 것을 읽어온다. 이 스킬은 그 포인트 하나에 필요한 재료 — 본문, 등장 객체, 관계, 시대 배경 — 를 온톨로지 소스(`points/`·`ontology/`)에서만 뽑아 붙여넣기 가능한 텍스트 한 덩어리로 조립한다.

한 번 호출에 포인트 1개만 다룬다. 여러 포인트를 비교하거나 포인트를 가로지르는 인물(예: 여러 장에 걸쳐 등장하는 하스드루발)의 전체 서사를 훑는 작업은 이 스킬의 범위가 아니다 — 필요하면 포인트별로 각각 호출해 조립된 덩어리를 나란히 둔다.

## 입력

- 포인트 번호 1개 (1~30). "2번", "제1차 포에니 전쟁 포인트" 같은 자연어도 `points/` 파일명으로 매핑해 번호를 확정한다.
- 레포 경로는 고정: `~/project/active/decline-and-fall-of-the-roman-empire/` (읽기 전용으로 다룬다).

## 절차

1. 번호를 2자리로 정규화(`2` → `02`)해 `points/NN_*.md` 파일을 연다. `00_목차`·`00_일러두기`·`00_책머리에`·`99_옮기고나서`는 30포인트가 아니므로 대상에서 제외한다.
2. 해당 파일 본문 전체를 읽는다. 제목, 소제목(`###`), 서술, 그리고 파일 끝의 `### 등장 객체` 절을 확보한다.
3. 등장 객체를 두 소스에서 모은다.
   - A: `### 등장 객체` 절의 카테고리별 목록(인물/지명/사건/집단/제도/저작 등, 책마다 카테고리 구성이 다를 수 있다).
   - B: `ontology/entities.jsonl`을 파싱해 각 줄의 `points` 배열에 해당 번호가 들어있는 엔티티 전체(`{id, name, type, points, desc, descs}`).
   - 두 목록은 어긋난다. 예를 들어 포인트 2는 A(본문)에 인물 8·지명 24·사건 3·집단 6·제도 1·저작 1 = 43개가 있고 B(entities.jsonl)에는 40개가 있는데, 겹치지 않는 항목이 양쪽에 다 있다.
   - A에는 있지만 B의 해당 포인트 목록엔 없는 경우가 두 유형으로 나온다.
     - 언급만 되고 별도 관계로는 안 잡힌 경우: `한니발`은 본문에 "하밀카르 바르카스(한니발의 아버지)"로 나오지만, `entities.jsonl`의 `person:한니발` 레코드는 `points: [3, 4]`뿐이고 2는 없다(3·4포인트에서 본격 등장하기 때문).
     - 중의어 링크가 엔티티 자체에 반영 안 된 경우: 본문엔 `[[그리스 (지명)|그리스]]`와 `[[그리스 (집단)|그리스]]`가 둘 다 걸려 있지만 `place:그리스`는 `points: [12, 21, 24, 29]`, `group:그리스`는 `points: [1]`이라 어느 쪽도 2를 포함하지 않는다.
   - B에는 있지만 A의 `### 등장 객체`에는 카테고리로 안 걸린 경우도 있다: `아그리젠토 포위`·`마르살라 만 해전`·`본 곶 전투`·`탈라모네 전투`·`팔레르모 탈환 시도` 같은 개별 event 엔티티가 그렇다. 본문 "등장 객체 > 사건"엔 `메시나 전투`·`제1차 포에니 전쟁`·`제2차 포에니 전쟁` 3개만 적혀 있다.
   - 합집합을 만들고 각 항목 옆에 `[본문]` / `[entities.jsonl]` / `[양쪽]`을 표시한다. 표시를 생략하면 다음 단계에서 왜 이 항목이 목록에 있는지 아무도 검증할 수 없다.
4. 합집합의 각 엔티티에 설명을 붙인다. `entities.jsonl`의 최상위 `desc`는 그 엔티티가 가장 비중 있게 다뤄진 포인트 기준 요약이라 다른 포인트에서 보면 어긋난다 — 반드시 `descs` 배열에서 `point`가 해당 번호와 일치하는 원소의 `desc`를 쓴다. `descs`에 해당 포인트가 없으면 `entities/<type>/<이름>.md` 노트 본문에서 가져온다.
5. `ontology/links.jsonl`을 파싱해 `point` 필드가 해당 번호와 정확히 일치하는 줄만 뽑는다(`from`, `to`, `rel`, 있으면 `from_year`/`to_year`/`year_basis`). 다른 포인트의 관계를 끼워 넣지 않는다.
   - 뽑은 관계의 `from`/`to` 엔티티 ID를 3번 합집합과 다시 대조한다. `entities.jsonl`의 `points` 배열과 `links.jsonl`의 `point` 필드는 서로 다른 소스라 이 둘도 어긋난다 — 예를 들어 `person:한니발`의 `points`는 `[3, 4]`뿐이라 3번 B에서는 빠졌지만, `links.jsonl`엔 `person:한니발 → group:젊은사자들 (member_of)`가 `point: 2`로 버젓이 있다. 이런 항목은 합집합에 `[links.jsonl]`로 추가한다.
6. `ontology/chronology.csv`에서 해당 시기 구간(본문 서술의 연도, 또는 5번에서 뽑은 `from_year`/`to_year`)에 걸리는 행을 찾는다. `chronology.csv`는 82행뿐이라 성긴 연표다 — 구간 안에 행이 하나도 없는 포인트가 흔하다(예: 포인트 2의 기원전 264~241년 구간엔 행이 0개, 앞뒤로 가장 가까운 행은 기원전 509년과 기원전 60년). 없으면 "해당 구간 연표 없음"이라고 명시하고 멀리 떨어진 행을 억지로 끌어오지 않는다.
7. 필요하면 3~4에서 뽑은 핵심 엔티티(주요 인물·사건 위주, 전체는 아님)의 `entities/<type>/<이름>.md` 노트를 열어 노트 자체의 `### 관계` 절을 5번에서 만든 관계 목록과 대조한다. 둘이 다르면(노트가 더 최근에 갱신됐거나 반대로 낡았을 수 있다) 둘 다 남기고 불일치를 그대로 노출한다 — 임의로 한쪽에 맞춰 지우지 않는다.
8. 1~7을 아래 출력 형태로 조립한다.

## 하지 말 것

- `source/`·`chapters/`를 열지 마라. 기번 영문 원전 계통이고 30포인트와 다른 책이다. 온톨로지(`entities.jsonl`/`links.jsonl`/`chronology.csv`)는 30포인트 계통에서만 뽑았다.
- 본문 위키링크 개수로 등장 객체를 세지 마라. 부분적으로만 박혀 있다(포인트 2 본문엔 위키링크가 91개 있지만 히에론·시라쿠사 같은 이름도 처음 등장 이후엔 링크가 빠진 곳이 있다). 반드시 `### 등장 객체` 절 + `entities.jsonl`의 `points` 필드 둘 다 확인한다.
- `links.jsonl`에 없는 관계를 지어내지 마라. 본문 서술상 그럴듯해 보여도 `point`가 일치하는 줄이 없으면 "관계 없음"이다.
- 본문 서술을 그대로 사실로 단정하지 마라. 편역본에 오류가 있다(포인트 1·2 45건 검증에서 심각 6건, 전투 승패가 뒤집힌 곳이 두 장에 하나꼴). 사실 검증이 필요하면 이 스킬이 아니라 `fact-check` 스킬로 넘긴다.
- 기원전 연도의 음수 부호를 떨어뜨리지 마라. `from_year`/`to_year`/`chronology.csv`의 `year`는 기원전이 음수다. 양수로 옮기면 500년이 어긋난다.
- `from_year`가 `to_year`보다 항상 이전이라고 가정하지 마라. 뒤집힌 줄이 실제로 있다(`event:제1차포에니전쟁 → place:로마`, `occurred_at`, `from_year: -241, to_year: -264` — 전쟁은 기원전 264년에 시작해 241년에 끝났는데 필드 순서는 반대다). 출력할 땐 필드 순서가 아니라 두 값 중 더 이전 연도를 시작으로 표시한다.
- 합집합 없이 한쪽 소스만 쓰지 마라. 본문만 쓰면 `아그리젠토 포위` 같은 개별 사건 엔티티가 빠지고, entities.jsonl만 쓰면 `한니발`처럼 이름만 언급된 인물이 빠진다.
- 다른 포인트에서 본 카테고리 구성을 그대로 기대하지 마라. `### 등장 객체`의 카테고리(인물/지명/사건/집단/제도/저작 등)는 포인트마다 다르게 구성될 수 있다 — 포인트 2에 있는 카테고리가 다른 포인트엔 없거나 새 카테고리가 추가될 수 있으니 그 포인트 파일에 실제로 적힌 대로 따른다.

## 출력 형태

아래는 포인트 2를 예로 든 뼈대다. 실제 산출물은 이 구조를 그대로 채운다.

```
# 포인트 2 — 제1차 포에니 전쟁

## 본문
(points/02_제1차_포에니_전쟁.md 전문, 소제목 포함)

## 등장 객체 (합집합, 출처 표시)
- 인물
  - 히에론 [양쪽] — 시라쿠사의 왕. 마메르티니 용병대를 토벌하려 메시나를 포위했으며 후에 로마와 부전동맹을 맺음.
  - 하밀카르 바르카스 [양쪽] — 한니발의 아버지. 카르타고 군 총사령관으로 로마의 보급기지를 공격함.
  - 한니발 [본문 + links.jsonl] — `entities.jsonl`의 `points`는 `[3, 4]`뿐이라 B엔 없지만, `links.jsonl`엔 `person:한니발 → group:젊은사자들 (member_of)`가 point 2로 있음
  - 마고 [entities.jsonl] — 본문 "등장 객체 > 인물" 목록엔 미기재
  - 레굴루스 [양쪽] — 로마의 지휘관. 카르타고의 강화 제의를 일축했으나 본 곶 전투에서 패해 포로가 되었고 고문 끝에 살해됨.
  - 크산티포스 [양쪽] — 스파르타 출신의 그리스인 장군. 카르타고를 구하기 위해 기병대와 코끼리 부대를 이용한 새로운 전술을 고안함.
- 지명
  - 시라쿠사 [양쪽], 카르타고 [양쪽], 메시나 [양쪽] ...
  - 그리스 [본문] — `place:그리스`(points 12,21,24,29)·`group:그리스`(points 1) 모두 2를 포함하지 않음. 본문엔 지명·집단 두 중의어 링크로만 존재
  - 스파르타 [entities.jsonl] — 본문 "등장 객체 > 지명" 목록엔 미기재(크산티포스의 출신지로만 서술)
- 사건
  - 메시나 전투 [양쪽], 제1차 포에니 전쟁 [양쪽]
  - 아그리젠토 포위 / 마르살라 만 해전 / 본 곶 전투 / 탈라모네 전투 / 팔레르모 탈환 시도 [entities.jsonl] — 본문 "등장 객체 > 사건"엔 미기재, 서술로만 존재
- 집단 / 제도 / 저작
  - 마메르티니 [양쪽], 백인대회 [양쪽], 까마귀 전함 [양쪽]

## 관계 (links.jsonl point=2, 총 43건)
- 클라우디우스 풀케르 → 메시나 전투 (participated_in, 기원전 264년, year_basis: text)
- 한노 → 카르타고 (ruled)
- 히에론 → 시라쿠사 (ruled)
- 히에론 → 로마 (allied_with)
- 하밀카르 바르카스 → 카르타고 (ruled)
- 하밀카르 바르카스 → 로마 (opposed)
- 크산티포스 → 카르타고 (ruled)
- 하스드루발 → 카르타고 (ruled)
- 하스드루발 → 하밀카르 바르카스 (succeeded)
- 제1차 포에니 전쟁 → 로마 (occurred_at, 기원전 264~241년)
- 제1차 포에니 전쟁 → 카르타고 (occurred_at, 기원전 264~241년)
- 로마 → 시칠리아 (ruled, 기원전 241년~)
- 로마 → 사르데냐 섬 (ruled, 기원전 241년~)
- 마메르티니 → 메시나 (ruled)
- 마메르티니 → 로마 (allied_with, 기원전 264년)
- 하밀카르 바르카스 → 마르살라 만 해전 (participated_in, 기원전 256년)
- 레굴루스 → 본 곶 전투 (participated_in, 기원전 255년)
- 하스드루발 → 팔레르모 탈환 시도 (participated_in, 기원전 250년, year_basis: inferred)
- 한니발 → 젊은 사자들 (member_of)
- 하밀카르 바르카스 → 젊은 사자들 (created)
(총 43건 중 발췌. year_basis가 `chronology`/`inferred`인 줄은 연도가 본문 직접 서술이 아니라 보강 추정임을 표시한다)

## 시대 배경 (chronology.csv)
해당 구간(기원전 264~241년) 연표 없음. 가장 가까운 행: 기원전 509년(왕정 폐지·공화제 시작), 기원전 60년(제1차 삼두정치) — 참고용으로만 표시, 포인트 본문과 직접 연결되지 않음.
```

이 블록이 산출물 전체다. 앞뒤에 "여기 정리했습니다" 류의 안내문을 덧붙이지 않는다 — 그대로 복사해 다른 AI의 입력창에 붙여넣을 수 있어야 한다. `entities/<type>/<이름>.md` 노트와 대조해 불일치가 나온 항목이 있으면 "등장 객체" 또는 "관계" 절 해당 줄 옆에 `(노트와 불일치: ...)`로 짧게 덧붙인다.
